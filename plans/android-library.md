# Implementation Plan: Native Android library `pushharbor-android` (PH-34)

## Overview

Extract the Android client from `packages/expo` into a standalone Kotlin library
(`packages/android`, package `io.github.singhgur.pushharbor`) that native apps can use
directly; the Expo module becomes a thin JS bridge over it, bundled as a Gradle subproject in
the npm package. JS API and on-device behaviour stay unchanged.

## Planning Profile

- Executor: Workhorse
- Detail: Standard

## Global Context

- Current Android code: `packages/expo/android/src/main/java/dev/pushharbor/expo/`
  (`Registrar.kt`, `Subscriptions.kt`, `PushService.kt`, `Envelope.kt`, `Rfc8291.kt`,
  `PushharborModule.kt`) and `src/test/.../SpecVectorsTest.kt`. Only `PushharborModule.kt`
  uses Expo APIs.
- Toolchain in the Expo example (`examples/expo/android`, generated by prebuild): AGP 9.2.1,
  Gradle 9.4.1, Kotlin 2.2.0, `android.builtInKotlin=false`, `android.newDsl=false`,
  compileSdk 37, minSdk 24. CI uses Temurin 17.
- Expo autolinking (`expo-modules-autolinking`) supports `android.projects: [{name, path}]` in
  `expo-module.config.json`: extra Gradle projects included by the app's settings.
- Release `npm-pack` job runs `npm ci && npm pack` (unprivileged), so `prepare` runs there.
- `scripts/check-logging.py` scans `packages/expo/android/src/main/**/*.kt`.
- `examples/expo/scripts/send.mjs` reads `{endpoint, keys}` from `$SUB`; extra fields are fine.

## Architecture Decisions

1. Kotlin package and Android namespace: `io.github.singhgur.pushharbor`. Maven coordinates
   `io.github.singh-gur:pushharbor-android` (publishing is PH-35, not here). The Expo module
   keeps `dev.pushharbor.expo`.
2. `packages/android/` is a standalone Gradle build (own `settings.gradle`, wrapper,
   `gradle.properties` with `android.useAndroidX=true`, `android.builtInKotlin=false`,
   `android.newDsl=false`). Its `build.gradle` must also work as subproject
   `:pushharbor-android` inside an app: plugin IDs without versions (versions live in
   `settings.gradle` `pluginManagement`), no `repositories` block in `build.gradle`,
   `compileSdk rootProject.ext.has('compileSdkVersion') ? rootProject.ext.compileSdkVersion : 37`,
   `minSdk 24`, Java/Kotlin target 17.
3. Bundling: `packages/expo/scripts/sync-android.mjs` copies `packages/android/build.gradle`
   and `packages/android/src/main` to `packages/expo/android-lib/` (deleted first;
   gitignored). `prepare` becomes `node scripts/sync-android.mjs && tsc`. `files` adds
   `android-lib/build.gradle` and `android-lib/src/main`. `expo-module.config.json` adds
   `"projects": [{"name": "pushharbor-android", "path": "android-lib"}]`; Expo
   `build.gradle` adds `implementation project(':pushharbor-android')`.
4. Upgrade compatibility, unchanged names: SharedPreferences `pushharbor`, Keystore alias
   `pushharbor_wrap`, notification channel `pushharbor`, meta-data
   `dev.pushharbor.notification_icon`, log tag `Pushharbor`.
5. Public API (everything else `internal`):
   ```kotlin
   object Pushharbor {
     suspend fun register(context: Context, relayUrl: String, senderKey: String): PushSubscription
     suspend fun subscriptions(context: Context): List<PushSubscription>
     suspend fun unregister(context: Context, id: String)
     @JvmStatic fun registerAsync(context, relayUrl, senderKey): CompletableFuture<PushSubscription>
     @JvmStatic fun subscriptionsAsync(context): CompletableFuture<List<PushSubscription>>
     @JvmStatic fun unregisterAsync(context, id): CompletableFuture<Void?>
     @JvmStatic fun refreshTarget(context)            // async rotation check (was Expo OnCreate)
     @JvmStatic fun addMessageListener(listener: MessageListener)
     @JvmStatic fun removeMessageListener(listener: MessageListener)
     @JvmStatic fun needsNotificationPermission(context): Boolean
     @JvmStatic fun needsLocalNetworkPermission(context, relayUrl): Boolean
     const val LOCAL_NETWORK_PERMISSION = "android.permission.ACCESS_LOCAL_NETWORK"
   }
   fun interface MessageListener { fun onMessage(message: Message) }
   data class Message(title, body, url, tag, data: String?)   // was Envelope; parse/visible internal
   class PushSubscription(id, endpoint, p256dh, auth) { fun toJson(): String } // JS shape incl. id, expirationTime null
   class PushharborException(code: String, message: String)   // ERR_* consts in companion
   ```
   - Async functions run on the existing single-thread `Registrar.executor` via
     `CompletableFuture.supplyAsync`; suspend versions `await()` them
     (`kotlinx.coroutines.future.await`, dependency `kotlinx-coroutines-core:1.10.2`).
   - Any non-`PushharborException` inside them becomes
     `PushharborException("ERR_PUSHHARBOR", e.javaClass.simpleName)`.
   - `register` throws `ERR_LOCAL_NETWORK` when `needsLocalNetworkPermission` is true.
   - `subscriptions` drops entries whose keys can't be unwrapped (current `getSubscriptions`
     rule); a `PushSubscription` carries the unwrapped `auth` as base64url.
   - Listeners: `CopyOnWriteArrayList`, called on the FCM service thread for every decrypted
     message; `PushService` calls internal `Pushharbor.dispatch(message)`.
6. Expo `PushharborModule` uses only the public API: listener added in `OnCreate`, removed in
   `OnDestroy` (replaces static `emit`/`WeakReference`); `refreshTarget` in `OnCreate`; keeps its
   own `ERR_LOCAL_NETWORK` pre-check message and Expo permission prompts. `src/index.ts`
   unchanged.
7. Native example `examples/android`: app ID/namespace `dev.pushharbor.nativeapp`, one plain
   `android.app.Activity` (programmatic views, `Theme.Material.Light`, icon
   `@android:drawable/sym_def_app_icon`), deep link `pushharbornative://register?relay=&key=`,
   writes `files/subscription.json` (last `PushSubscription.toJson()` or `null`). Includes the
   library via `settings.gradle` (`projectDir = file('../../packages/android')`).
   `app/google-services.json` gitignored; `app/google-services.placeholder.json` committed.
8. `docs/android.md` documents installing via source include for now; PH-35 switches it to the
   Maven line. Publishing config stays out of `build.gradle` (PH-35 must keep it in a file only
   the standalone build applies).

## Assumptions

- Gradle runs on the default JDK 25; if not, use `JAVA_HOME=~/.local/jdks/temurin-17`.
- One commit per phase on `main`, after the user confirms the phase.
- Device checks use the native relay (`just example-relay`) only; Workers is not re-run.

## Phase Strategy

1 → (2, 3 in either order) → 4. Each phase leaves the repo building and tested.
